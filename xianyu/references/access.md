# 使用当前宿主访问闲鱼

技能负责理解需求、核查与比较。真实商品由宿主提供的浏览器或已连接闲鱼工具读取；不要求用户运行脚本、设置环境变量或把登录凭证发进聊天。

## 先确认登录并执行

在商品搜索前主动询问用户现在是否方便登录闲鱼。用户同意即执行当前宿主提供的登录操作，不再次询问是否开始；不要先搜到访问受限后才提出登录。

有可复用且已授权的会话时先核验，仍有效就直接使用。用户已明确允许登录但尚未完成时继续流程，不重开授权问答。没有现成会话时，优先用已连接工具实际提供的登录能力，或打开闲鱼官网的登录入口。只在同一受控环境中处理登录，不假设手机或另一浏览器会话会自动同步。

扫码、手机确认、短信验证等由用户在相应入口完成；Agent 负责打开入口、展示本次二维码、检查状态，并在确认登录成功后继续需求澄清与搜索。不把二维码生成、用户扫码或工具调用未报错当成登录成功。不要求把密码、验证码、Cookie 或扫码凭证粘贴进聊天。

用户暂不方便或不愿登录时，使用可以读取的公开内容或已有材料并说明范围。登录入口不可用或登录失败时说明具体阻塞，不编造已登录，也不反复重试验证。登录授权不包含发消息或交易，后续按各自实际授权执行。

## 已有闲鱼工具

先读实际工具说明，确认搜索、分页、详情、规格、卖家记录等能力。只使用已连接、已授权的工具，不虚构工具名、服务器地址、开放 API 或跨环境共享的登录态。

检查返回是否明确成功，以及数据的来源与采集时间。登录过期、限流、验证码或解析失败不能说成“没有商品”。搜索卡片只提供线索；对候选继续读取目标规格、库存、适用条件和费用。

全站买家搜索与卖家店铺管理是不同能力。不要把某店的商品/订单管理接口当作全站货比三家。只读查询不需要顺便开启消息、发布或交易能力。

## 浏览器

1. 沿用用户指定的浏览器、标签页或已有会话，访问[闲鱼官网](https://www.goofish.com/)。根据当前页面寻找搜索入口，不复用旧页面的元素编号或固定选择器。
2. 用户已经同意登录时，直接打开或使用当前登录入口，完成必要的用户确认并核验状态。用户选择暂不登录时，若弹窗能关闭则继续查看公开内容；不能把其选择改成默认同意登录。
3. 使用页面实际提供的筛选与分页。打开候选详情和可访问的卖家信息，保存真实链接及所选规格；不从标题编造详情地址。
4. 多规格商品逐项匹配名称、数量、实际价格与库存；零库存不进入可买排序。商品展示的运费不等于餐品配送费。
5. 门店、影院、场次与适用范围按品类参考继续查证。第三方商品能否在某店使用，不能只靠品牌有这家店来判断。

“我想要”“立即购买”可能打开聊天、选择规格，也可能进入交易流程。根据当前界面判断后果；没有相应授权时不触发消息、订单、锁座、出码或扣费。

## 需要询价时

先查公开条款和购买前可读的适用范围。仍缺关键信息时，准备具体卖家、商品和完整问题：目标门店/场次、规格与数量、日期时段、实付总额、补差、交付和失败处理。

已有联系授权就在范围内发送，无需重复询问；尚未授权则请求联系授权。用户选择暂不联系时停止发送，明确目前无法确认的内容。只读取本次询价涉及的对话，不顺带浏览无关聊天。消息发送成功不代表已拿到有效答复；模糊回答要继续澄清。

## 能力不足时

| 当前能读到什么 | 能作出的判断 |
| --- | --- |
| 实时详情、准确规格及关键适用依据 | 核查完成后可以比较与推荐 |
| 搜索列表可读，详情或目标规格不可读 | 候选线索，不能称最终报价 |
| 只有搜索引擎摘要 | 索引线索，继续验证详情与时效 |
| 只有用户给出的截图或材料 | 结论仅覆盖这些材料 |
| 没有实时商品读取能力 | 说明缺少浏览器或连接器，保留已理解的需求 |

遇到持续风控或访问错误时停止反复请求，说明具体阻塞及可采取的下一步。不能把计划、缓存或失败请求说成已经完成的实时查询。
