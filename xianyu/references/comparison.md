# 比较与证据

## 先核查，再排序

对每个候选保留：实际来源链接、卖家标识、目标规格与数量、采集时间、费用、具体适用地点与时段、交付办法、失败与售后条款，以及相关卖家公开记录。

关键事实标明“页面明确 / 卖家针对本次条件确认 / 待核实 / 不满足”。卖家文字不能升级为平台保障；好评、认证或销量也不能证明某张券在指定门店可用。

按以下状态处理：

- **排除**：明确不满足硬条件，所选规格已售罄/过期，或要求站外付款、登录凭证、提前确认收货等。
- **待核实**：目标规格、供给、完整费用、门店/场次适用、时限、交付或失败处理等关键项仍未知。继续查证；确实阻塞时说明缺口，不让它成为最低可买推荐。
- **基础条件已核查**：需求适配、有效供给、完整总价、平台内交易、交付方法及失败/售后条款都有当前依据。餐饮、电影等必须记录具体门店/影院、地址和本商品规格/场次的适用来源。
- **证据更充分**：基础项成立，还观察到相关品类的近期评价或其他可核验记录。表达信息更多的具体依据，不给安全概率。

售后条款已知不等于一定可以退款；不接受的条款仍使该候选不满足用户需求。没有附加卖家记录也不自动等于有风险。

## 统一费用口径

**本次总支出 = 本次购买数量对应的商品或服务金额 + 运费/配送费 + 服务费及必付补差 − 本次确实可用的优惠。**

- 比满足本次数量的整单支出，再展示每块/张/件价格。两块与两对、票面价与含服务费票价、订金与全款分别核对。
- 套餐才能得到目标商品时，计入整套支出，不把用户没要求的饮料等自行折现扣除。大套餐多出的数量和支出写清楚。
- 费用缺失是未知，不能填零。最低消费、起购、会员、限定人群、配送或门店补差也属于本次条件。
- 优惠必须确认本次可用且计入规则明确。可退押金单列，仍计入当次需要支付的资金，并区分最终消费成本。
- 金额按币种的实际精度计算；不同币种、规格或单位先统一，无法统一时分组比较。

## 给出可审阅的选择

从满足用户条件与保障偏好的已核查候选中选最低整单支出；存在保障证据更充分的备选时，写清价差和多出的依据。用户侧重时效、保障或价格时据此调整，不用自创权重替用户决定。

商品有库存不等于目标门店有餐，也不等于这张券在该店适用。所选规格、具体地点、时间、完整总价和失败处理要能对上同一次需求。

写明查询时间与比较范围，例如查看条目数、独立卖家数；重复链接不能算多个卖家。只称“本次已核实候选中最划算”，不宣称全网最低。没有合格候选时继续处理可解决的缺口，或明确当前阻塞。

官方渠道同条件现价能取得时可计算节省金额；取不到就不编省了多少，不拿卖家划线价充当官方现价。
