# 餐饮、电影与其他消费

只读当前品类对应部分。这里列的是核查方式，品牌菜品、活动价格、门店和规则都需以当次页面为准。

## 餐饮：从“想吃”到吃得到

### 意图翻译

用户：“我想吃奥尔良烤翅。”

保留“奥尔良口味 + 烤翅”这两个核心条件。暂按现成熟食找，并补城市/商圈、几块、自取或外送、什么时候吃。不要直接问“你要搜索哪个关键词”。

搜索可从“奥尔良烤翅”开始，按结果扩展“新奥尔良 烤翅 代下单”“奥尔良烤翅 餐券”。看到实际品牌餐品后，再搜该品牌与对应餐品；肯德基只是可能的候选，不能成为未经用户选择的默认唯一品牌。搜索不到精确餐品时，说明问题，再提供不同品牌或相近餐品备选。

### 逐项核查

| 条件 | 核查要点 |
| --- | --- |
| 实际餐品 | 全翅/翅中/翅根；烤/炸；口味；块/对/份；套餐是否确实能选该餐品 |
| 当次需求 | 用户只要 4 块时，10 块桶可能单价更低，但整单支出和多余份量要说清 |
| 交付 | 自取、堂食、外带或外送；自动发链接不等于自动出餐；能否直接取餐 |
| 门店 | 具体城市/门店适用性；车站、机场、景区等排除条件；“全国通用”有没有例外 |
| 时间 | 当天供应时段、营业时间、预约或预售日期；发券速度不等于出餐或送达时间 |
| 支出 | 目标餐品的实际规格价、服务费、补差、配送/跑腿费、最低消费或另购条件 |
| 失败处理 | 门店无货、下单失败、未使用、出取餐码后分别怎么处理；承诺来自哪里 |

### 门店核验与完成条件

用户给出城市/商圈后，先用品牌门店查询、官方点餐或可靠地图找少量可自取的具体分店，记录全名和地址。不要把一个商圈自行等同于某一家店；需要时让用户从查到的门店中选择，或再问附近地标。距离和步行时间只有取得定位或路线依据才展示。

再验证 **这件商品的这个规格，在这家分店、这次时间和取餐方式可用**：优先读取与该商品关联的门店清单、购买前可访问的选店/报价页面，或已有的卖家针对本次条件的明确答复。品牌官方菜单能证明该店有此餐品，但不能单独证明第三方券能用；地图、银行别的活动名单也不能代替本券的适用证据。卖家确认按“卖家已确认”表述，不能改称平台已验证。

核查目标规格的名称、份量、价格与库存；主图/标题价和最低价均不能取代规格价，零库存直接排除。虚拟商品展示零运费，不能由此推出餐品外送免费。自取也需排查服务费或门店补差，未说明就是未知。

若只写“付款后发链接选店”，购买前看不到支持范围，不为验证而买券。先查商品其他公开说明；仍缺证据且已有联系授权时，向卖家询问具体门店及两种份量的实付总价、可用时段、补差、无货/失败退款。没有联系授权时，准备好卖家、商品和问题再请求授权；不擅自发消息，也不把“你自己问一下”当完整交付。

至少确认一套“具体门店 + 确切规格/数量 + 完整总价 + 当次时段 + 取餐方式 + 失败处理”的组合，才交付购买推荐。否则继续解决缺口或明确当前阻塞，不宣布最低可买价。确定的是当前来源支持的条件，不保证之后库存或履约永远不变。

“奥尔良烤翅根”“奥尔良烤鸡腿堡”“香辣鸡翅”“冷冻烤翅”都不能悄悄替代用户的精确需求。用户允许时才列为替代，并标明差异。

只接受外送时，自取餐券不算满足要求。可以比较“自取券 + 已核实跑腿费用”的组合，但必须得到用户对这种交付方式的接受；没有可靠配送报价时总价仍未知。

餐券链接可能要求输入城市和门店，也可能索取登录信息。不要向卖家或陌生点餐页提供品牌账号密码、验证码；不要仅凭相似 Logo 就认为是品牌官网。尚未购买的领取链接不是验证手段。出码/核销/确认收货须按授权执行。

### 对话示例（示范行为，无真实报价）

用户：我想吃奥尔良烤翅。

Agent：我先按现成的烤翅来找，看看单点和套餐哪个划算。你在哪个城市、附近什么商圈？大概想吃几块，自取还是外送？

用户：上海五角场，4 块，自取，今晚吃。

Agent 的下一步：找匹配的烤翅现有选项，核对附近门店、今晚供应和 4 块整单价格；预售到明天、只卖冷冻食品、卖烤翅根或必须买大套餐的分开处理。无授权时不自行联系卖家。

用户已给地点和自取方式、但没给份量时，先找该区域实际分店，可分别核对小份和常见份量的报价。即使商品规格有库存且标价便宜，也要继续确认适用分店。无法确认时提出缺少的具体问题，不输出“某家最低，门店待核实”作为最终答案。

用户明确说“想点个 KFC”时，沿用肯德基品牌范围；没选好餐品就根据人数、预算和口味找合适组合，再比较代下单与卡券。只有用户接受，才把其他品牌作为替代方案单独列出。

## 电影：从“想看”到具体场次

“想看电影”但没选片：问城市、时间、人数和大致偏好，利用当次排片提出少量影片/影院选项。用户已给片名时直接匹配，不重复问偏好。

只有城市范围的搜索结果还不足以确定某场可用。逐项确认：

- 影院全称与分店、影片、日期、场次、版本/语言、影厅类型、人数、连座/座位要求。
- 商品是代订具体场次、通兑券、团购券还是某种会员权益；能否覆盖目标场次。
- 单张总价及整单总价：服务费、IMAX/杜比/特殊厅补差、热门时段、城市分级、最低起订数。
- 出票耗时、失败处理、出票后退改规则、票券有效期与适用影院，分别标记来源。
- 可以通过影院或可信的官方购票渠道核对的订单/票信息；仅一张截图或一句“保证出票”不等于已验证入场资格。

不能把电影票挂牌 ¥1 当出票价；“28 元起”“全国通兑”需要具体场次报价。临近开场时，看清 **实际出票承诺** 和座位状态；拿不到就不给确定的赶得上承诺。不为比价占座、锁座、出码，也不公开取票码或让用户先确认收货。

## 卡券、生活服务与实物

| 类别 | 重点差异 |
| --- | --- |
| 奶茶、咖啡、餐券、商超券 | 杯型/品项、门店、最低消费、叠加/会员条件、期限、是否一次用完及余额处理 |
| 景区、演出等门票 | 日期/时段/场次、实名与转让限制、预约、可核验交付、退改；不能用电影票规则套用 |
| 代办、维修、设计等服务 | 交付范围、工期、修改/售后次数、额外收费、可验收产物；案例只是卖家展示 |
| 实物/二手数码 | 同型号版本、成色、配件、维修/故障、可见实拍与检测证据、运费、验货与退货条件 |

其他需求按“如何判断用得上、什么时候拿到、完整支付多少、失败怎么办”扩展核查，不要求用户先学会品类术语。不把信用标签当真伪鉴定，不把店家自称的官方货源当已验证授权。
